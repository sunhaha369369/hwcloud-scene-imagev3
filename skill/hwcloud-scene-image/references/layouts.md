# 三种版式骨架 · v2

版式只解决一个问题：**信息按什么动线走**。动线只有两种合法方向——**水平向右**，或**从上向下分叉**。禁止斜向长距离穿越，禁止绕圈。

v2 的前提：**元素总数 ≤ 7**。所以这里每种版式都只有「一个主体 + 3 个附属 + 1–2 个浮标」，不再有"六节点 + 微缩图表"那种信息密度。

---

## B · 上→下分叉（`template-b-flow.html`）

**适用**：输入→生成→多路产出、转换、整理、构建、流水线。

```
┌──────────────────────────────────────────────┐
│ 短标题                                        │
│ ┌────────┐                       ┌──────────┐ │
│ │▤ 画一张…│                       │✦ 一键插入 │ │
│ └────────┘                       └──────────┘ │
│      │                                        │
│    ⬢ 渐变瓦片 200                             │
│      │                                        │
│  ┌───┴────────────┬───────────┐               │
│  ▼                ▼           ▼               │
│ ┌──────┐       ┌──────┐    ┌──────┐           │
│ │时序图 │       │ER 图  │    │状态机 │           │
│ └──────┘       └──────┘    └──────┘           │
└──────────────────────────────────────────────┘
```

| 零件 | 参数 |
|---|---|
| 输入胶囊 | `690×136 / r68`，居中（中心 x=835），左内 34px 图标 46 + 48px 例句 |
| 渐变瓦片 | `200×200 / r52`，与输入胶囊同轴（x 中心 835） |
| 分叉总线 | 瓦片底 → 竖线 → **枢纽点** → 左右两段半总线 → 三路竖线 → 卡片；箭头等腰三角。**必须拆成独立 path，不能一条 path 转弯后分支**，写法见 SKILL.md「连线怎么画才不会断」 |
| 输出卡 | `360×120 / r32`，等距：left `255 / 655 / 1055`，中心 `435 / 835 / 1235` |
| 浮标 | `320×128`，右上，与输入胶囊顶对齐 |

**注意**：三张卡的 left 必须等距，且**卡片中心要正对箭头**。手写坐标后务必核对 `left + 180 == 箭头 x`。

## C-1 · 画布编辑态（`template-c-ui.html`）

**适用**：既讲"一句话生成"，又讲"生成后还能改"。

```
┌────────────────────────────────────────────────┐
│ 短标题                                          │
│ ⬢170  ┌──────────────────────────┐  ┌────────┐ │
│       │▤ 画一张订单支付的架构图     │  │✦ 局部可改│ │
│       └──────────────────────────┘  └────────┘ │
│ ┌────────────────────────────────────────────┐ │
│ │ ┌──────┐  ┏━━━━━━┓  ┌──────┐               │ │
│ │ │网关   │  ┃订单 ▣┃  │数据库 │               │ │
│ │ └──────┘  ┗━━━━━━┛  └──────┘               │ │
│ │            ┆                               │ │
│ │        ╭──────────╮                        │ │
│ │        │✎ 改成异步 │                        │ │
│ │        ╰──────────╯                        │ │
│ └────────────────────────────────────────────┘ │
└────────────────────────────────────────────────┘
```

| 零件 | 参数 |
|---|---|
| 渐变瓦片 | `170×170 / r44`，`left 248 / top 286` |
| 输入条 | `850×118 / r30`，`left 450 / top 312`（与瓦片间隙 32） |
| 画布底板 | `1160×352 / r36`，`left 240 / top 486` |
| 三节点 | `330×132`，left `290 / 655 / 1020`（间距 35），top 526 |
| 选中节点 | 中间那个：`5px` 蓝边 + 12px 光晕 + 四角手柄 |
| 指令气泡 | `430×112`，居中于选中节点（left 605），top 706 |
| 气泡连线 | 4px 虚线，x 对准节点中心（820），`top 670 → 704`，**需 `z-index:6`** |
| 浮标 | `320×128`，右上，`left 1312 / top 300` |

**关键**：气泡虚线一定要画在节点之上，否则会被选中光晕盖掉。画布底板让"节点 + 气泡"成为一组，否则画面会散。

## C-2 · 分层选中态（`template-c-arch.html`）

**适用**：强调"只改一块、其余不动"的增量演进。**缩略可读性最好，拿不准就选它。**

```
┌──────────────────────────────────────────────┐
│ 短标题                                        │
│ ┌────────────────────────────┐  ┌──────────┐  │
│ │ ◎ 接入层                    │  │⊹ 仅改此块 │  │
│ └────────────────────────────┘  └──────────┘  │
│ ┌────────────────────────────┐  ┌──────────┐  │
│ │ ▦ 服务层              ⬢104  │  │✦ 布局不变 │  │
│ └────────────────────────────┘  └──────────┘  │
│ ┌────────────────────────────┐                │
│ │ 🗄 数据层                    │                │
│ └────────────────────────────┘                │
└──────────────────────────────────────────────┘
```

| 零件 | 参数 |
|---|---|
| 层条 | `910×152 / r36`，`left 250`，top `294 / 486 / 678`（间距 40） |
| 层内 | 90px 图标块（距左 34）+ `50px/500` 层名（距内 30） |
| 选中层 | 中间那条：`5px` 蓝边 + 光晕 + 四角手柄 + 右内嵌 `104×104` 渐变瓦片 |
| 层间连线 | 4px 虚线，x=705（层条中心），穿过 40px 间隙 |
| 两个浮标 | `320×128`，`left 1312`，top `412 / 580`（间距 40） |

**注意**：层条不要放骨架条或二级文字——一条只写一个层名，是它缩略后仍清楚的原因。

## A · 中心辐射（无模板，用 `_blank-shell.html` 搭）

**适用**：一个中心服务 N 个场景、能力辐射、生态。

- 中心瓦片 `200`，居中偏上；3–4 个 chip `330×132` 沿**向下**方向辐射，间距 ≥40。
- 连线：瓦片下缘 → 竖线 → 枢纽 → 左右半总线 → 三路竖直落下。**只允许直角折线**，且每条折线拆成互不重叠的独立 path（枢纽 + 半总线 + 支线），否则容易漏段。
- 中心以外的元素不超过 4 个，否则回到噪点问题。

---

## 怎么选（快速判断）

1. 标题里同时有「生成」和「可修改」→ **C-1**
2. 标题讲「只动一处、其余不变」→ **C-2**
3. 标题是「A 变成 B」「多路产出」→ **B**
4. 标题是「一个中心服务 N 个场景」→ **A**
5. 拿不准 → **C-2**（结构最简单，缩略最清楚）

# v3 版式（图形化）

v3 不铺 content 白卡，图形直接浮在淡蓝面板上。版式少而稳，只有两种——因为 v3 的
变化来自**图形本身**（圆、叠页、箭头、点阵），不是来自新的排布。

## D · 核心分支（`template-d-orbit.html`）

**适用**：一个核心能力 → 多类产出、能力辐射、一个中枢服务 N 个场景。

```
┌──────────────────────────────────────────────┐
│ 标题                            ┌──────────┐ │
│                                 │✓ 一键插入 │ │
│   ⬤ 时序图          ⬤ 状态机     └──────────┘ │
│        ╲            ╱                        │
│         ╭──────────╮                         │
│         │  叠页+星  │  ← 核心（唯一渐变体）    │
│         ╰──────────╯                         │
│        ╱            ╲                        │
│   ⬤ ER 图           ⬤ 拓扑图                 │
└──────────────────────────────────────────────┘
```

| 零件 | 参数 |
|---|---|
| 核心圆 | `r180`（360），圆心 `(830,600)`；内部是**三张错位叠放的图页** + 右下角星芒，不是单个图标 |
| 白圆徽章 | `r88`（176），图标 108；两列 `x=470 / 1170`，两排 `y=410 / 710` |
| 标签 | 48px/600，居中于徽章正下方 24px，宽 190 |
| 分支线 | 5px `#B7D3F2`。「圆盘缘 → 20px 到枢纽 → 上下竖线 → 44px 短横贴徽章」；竖总线 `x=610 / 1050`，必须大于标签右缘 565 |
| 柔光 | 直径 860，圆心同核心 |
| 浮标 | 320×128，`left 1312 / top 300` |

**核心为什么不用一个图标**：放一个星芒只是"AI"的通用符号；换成三张叠页，"多张图"这层意思就自己长出来了。

## E · 圆形流水线（`template-e-pipeline.html`）

**适用**：A → B → C 三步、输入→处理→产出、上传→解析→入库、构建→测试→发布。

```
┌────────────────────────────────────────┐
│ 标题                    ┌──────────┐   │
│                         │✓ 全程自动 │   │
│   ⬤ ──➤ ⬤(渐变) ──➤ ⬤  └──────────┘   │
│  上传     解析      入库                │
└────────────────────────────────────────┘
```

| 零件 | 参数 |
|---|---|
| 步骤圆 | `r135`（270），圆心 `y=568`，`x=395 / 820 / 1245` |
| 图标 | 132px，stroke 1.5 |
| 箭头 | 平头 + 尖头 `140×64`，居中于圆间隙（`left 537 / 962`, `top 536`），两侧各留 7px |
| 标签 | 56px/600，圆下方 24px |
| 中间圆 | 唯一渐变体，阴影加重一档，是整图视觉主体 |

**中间那块必须是核心环节**（解析、处理、生成），不要放第一步或最后一步——渐变位置就是读者的第一落点。

## v3 怎么选

1. 「一句话生成多种东西」「一个能力辐射多个场景」→ **D**
2. 「上传→解析→入库」「构建→测试→发布」这类三步递进 → **E**
3. 既有多类产出又强调"可以改" → 用 **D**，浮标写「局部可改」，把四个徽章中的一个换成 `tile-sel` 选中态
4. 要"分层架构"（接入 / 服务 / 数据）→ v3 暂无专用版式，用 `parts.html` 的 `.stackk` 层堆叠自行搭，或退回 v2 的 **C-2**

v3 的元素不够用时，先翻 `assets/parts.html` + `assets/parts-ext.html`（共 30 件）和 `assets/icons.svg`（100 枚），不要临时造新形状。
